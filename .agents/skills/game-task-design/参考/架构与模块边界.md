# 架构与模块边界

规范版本：0.4。下列是起步参考与可检查的边界，不表示当前工程已存在这些系统；实际已采用设计优先。

## 功能模块与内部职责是两个维度

先按玩家、门、背包、地图等功能组织，再在功能内部按实际需要分规则、引擎适配和表现。不要把全部玩法堆进 backend/、全部节点堆进 frontend/，也不要求每个模块都创建完整层级。

| 部分 | 输入与输出 | Godot 落地 |
|---|---|---|
| 纯规则 | 中立数据 → 计算/合法结果 | 函数、普通类或 RefCounted；适合独立计算时提取 |
| 引擎适配 | 物理/区域/生命周期事件 ↔ 明确状态 | CharacterBody3D、Area3D 等 Node；不为无节点重写物理 |
| 网络适配 | 意图、身份 ↔ 权威状态/结果 | 复用会话与权威入口；不每个模块建房 |
| 表现 | 确认状态 → 纸片/动画/音效/HUD；操作 → 意图 | 明确表现代理、场景节点，布局不掌管玩法状态 |
| 编排 | 当前对局依赖与行为顺序 → 一致变更 | 父场景/少量协调代码；不接管各机制内部实现 |
| 定义与状态 | 重量/配置定义；本局实例状态 | Resource 等定义按约定只读，运行态分离 |

例如 features/doors/door.tscn 组合碰撞与外观；确有独立规则时增加 door_rules.gd，表现复杂时增加 door_view.gd。小模块可在少量脚本内保持这些边界，无需空类。节点/类名 PascalCase，目录与文件英文 snake_case。

## 模块职责与依赖

| 模块 | 默认位置（相对 res://） | 负责 | 不直接负责 |
|---|---|---|---|
| Main / Session | app/；有需要才拆会话 | 入口切换、创建/加入、成员与连接结束 | 物品是否合法取得、战利品结算 |
| Match | app/match/ | 开始/结束、接线、派发权威流程、清理 | 背包重量公式和角色动画细节 |
| Player | features/player/ | 输入适配、角色主体、移动/个人行动状态 | 自行增加战利品或宣布全队胜负 |
| Interaction | features/interaction/ | 选择候选目标、提示与发交互请求 | 从客户端直接确认成功 |
| Doors | features/doors/ | 门状态、碰撞、表现与幂等应用确认结果 | 查特定 HUD、扣背包或新建网络管理器 |
| Items | features/items/ | 定义、地面实例、实例稳定标识 | 用客户端自报归属决定最终拾取 |
| Inventory | features/inventory/ | 数量/重量/容量和归属的规则与状态接口 | 查询某张地图或界面布局 |
| Enemy | features/enemies/ | 感知、导航适配、巡逻追逐、权威威胁结果 | 各客户端独立产生不同目标/伤害 |
| Escape | features/escape/ | 条件、等待和已确认个人结果 | 未经规则让一个人撤离后全队切图 |
| World | worlds/prototype_room/ 等英文目录 | 摆放模块实例、静态环境、出生点 | 复制玩家/门实现到每张地图 |
| UI | ui/ | 状态展示、按钮意图、本机反馈 | 写共享库存、血量或胜负最终值 |

以上是职责目录，不是首周必须实现的功能清单。玩家也可以包含表现子节点，不能仅凭“Player 有 Sprite”认定分层错误。

原则：子模块不钻外部固定私有路径；上层给依赖并接线。显式公开接口可以跨模块调用；没有必要不建全局事件总线。多个调用者已存在时才提取 shared/，不以将来可能用到为理由造框架。

## 用一次拾取理解规则、编排与表现

1. 本机输入/交互层选定物品并提出拾取意图，携带稳定标识，不直接写库存。
2. 房主入口从真实发送身份定位玩家，检查对局阶段、距离、目标存在及当前归属。
3. 背包规则用当前状态、容量和物品定义判断是否容纳，不查询地图/HUD。
4. 协调入口把归属转移与库存更新作为一次一致结果处理；失败不留下半转移状态。
5. 权威端同步确认结果；客户端按结果更新显示/音效。两人竞争只允许一次成功，重复结果不重复加物品。

房主本机也走相同规则；本地信号不是 RPC。房主可同时运行权威逻辑与自己画面，职责分离不要求额外部署后端服务。

## Godot 容易踩的边界

- Resource 按路径加载可共享实例；参数定义只读靠团队遵守。持有人、耐久和剩余数量等运行态不写回共享定义；复制资源时核对嵌套引用语义。
- 装饰动画、闪白、飘字不决定伤害与归属。攻击时点等有规则意义的动画协作需明确权威时序，不能让每个客户端按播放速度各算一次。
- 物理使用引擎步长与正确速度单位；倒计时/撤离由房主推进。先用 Timer、处理模式和物理回调，不先自建时间引擎。
- 每扇门不直接监听同一全局交互按键。先由输入/交互层选择目标；独立演练可以放输入测试壳，但标明尚未接入正式流程。
- 初始化、断线、场景卸载和重新开局要定义生命周期；旧引用、残留信号连接或旧局结果不能影响新局。

## 开工前的最小契约

每模块写：负责/不负责、目录与独立入口、输入/输出与公开方法/事件、状态拥有者与写入口、初始化/清理、正常/拒绝/重复/竞争行为、依赖和变更调用方。

多人并行使用独立工作目录；公共 project.godot、主地图、协议/接口先由当次指定编辑者更新。先交接口与最小实现，再顺序接下游；不强制 PR 或特定审核者。主责写真实任务，不按 A/B 示例任命真人。

## 按风险验证

| 行为 | 验证重点 |
|---|---|
| 更换表现 | 隐藏表现或停装饰动画，规则和碰撞仍正确 |
| 定义与实例状态 | 两实例共用定义时互不污染 |
| 子场景接入 | 换测试房只需显式依赖，不改内部规则 |
| 联机共享结果 | 房主/客户端均可请求；无效、重复和竞争受控 |
| 清理 | 退出再开一局不重复连接/奖励/留旧状态 |
| 迁移目录或接口 | 引用、UID、所有真实调用方与受影响入口可用 |

验证层次分开记录。首版暂缓确定性模拟、回滚/回放、通用依赖注入、万能数据库与全部事件总线，除非真实需求要求单独实验。
