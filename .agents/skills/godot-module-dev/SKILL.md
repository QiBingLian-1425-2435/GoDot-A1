# Godot 模块开发

沿项目既有路线完成一个可验证行为，交付队友能运行和接手的改动。
不因为调用技能就新建游戏框架、升级引擎或改写其他人的模块。本包自带必要规范与参考，可单独使用。

## 开工定位

1. 确认任务实际工作目录与项目根；有 Git 时读取分支、基线提交和工作区差异，保留无关成果。
2. 读取本包 [团队默认约定](参考/团队默认约定.md)，涉及规则、表现或跨模块变化时读 [架构与模块边界](参考/架构与模块边界.md)，再读取目标项目已有的相关设计、接口和任务。
3. 包内参考相对本技能目录解析，工程文件相对实际工程定位；没有作者仓库指南不阻塞工作。用户和实际项目的已采用约定优先。
4. 找到真实 `project.godot`、采用的精确 Godot 版本、相关场景树、脚本与当前启动入口；仓库根不一定是资源根。
5. 确认文件范围、共享文件当次编辑者、权威状态位置、任务依赖和验收；已有清晰任务不强制重新设计。
6. 检查本目录是否已有写入会话。并行写入使用不同 clone 或正确 worktree，避免同一目录切分支影响队友。

能运行就先验证相关基线，记录已有失败；没有引擎、工程或依赖时准确说明，不能声称验证通过。
用户没有要求创建工程或初始化 Git 时，不因缺失而擅自创建。
用户明确要求从零建立工程或整体目录迁移时，可采用 `godot-project-setup` 流程。日常开发中新建的目录与运行文件遵循共用规范的英文 `snake_case`，不为了增加一个功能重排全工程。

## 需求落位检查

先按项目入口读取共同目标与实际结构，再确定本次属于已有模块扩展、独立新职责还是架构变化。局部需求放回已有模块；独立职责才新增英文功能目录；新物品/皮肤通常扩定义或表现，不新建系统。小任务只需简短交代目标对应、模块归属、路径、状态写入者和验收，不强制新建设计文件。

新增机制放所属功能模块，入口组织接线，避免继续堆进 main。公共配置、地图、RPC、状态归属变化列出调用方与当次编辑者；在用户授权范围内完成必要调整，真实并行冲突或关键未决选择才协调。确需跨模块重构时先给最小接口迁移方案，其他技能不可用也可完成。新增/迁移后同步结构说明、接口与任务，检查 UID、引用和受影响入口。项目自身目录优先，根目录工程 + docs 与 game/ 布局都有效。

## 选择本次需要的参考

- 创建/改动子场景、配置资源或替换表现：读 [场景与资源](参考/场景与资源.md)。
- 涉及共享状态、RPC、移动碰撞或计时：读 [联机与物理](参考/联机与物理.md)。
- 遇到报错、导入问题或行为不符合预期：读 [问题诊断](参考/问题诊断.md)。

参考不是固定实现模板。以真实节点、采用中接口和匹配版本的内置/官方文档为准。
不为每个小改动加载全部材料，也不凭记忆拼接不同 Godot 大版本的 API。

## 保持范围，做最小实现

- 简短说明本次行为、拟改位置与验证入口，然后完成已授权范围，不每一步重复询问许可。
- 纯计算规则可用函数或普通类；移动、碰撞、区域检测继续使用合适 Node，不为“无节点”重写引擎。
- 机制接受明确输入，编排组织流程；父级接线，子场景不钻进外部固定树路径。
- 表现读取已确认状态并发送操作意图，不直接改共享最终结果；本地装饰动画不决定伤害、归属或胜负。
- 定义配置按约定只读，运行态独立；只提取需要调节的参数，不把所有技术常量搬进数据库。
- 保持现有公开接口。确需变化时先写清差异、调用方和依赖顺序，避免悄悄破坏队友实现。
- 必须改公共配置/网络入口/主地图且超出当前任务时，列出最小协调项；继续不受阻部分，不另造管理器绕过边界。
- 美术替换任务优先只换资源与表现适配，不附带重构数据库、玩法或网络层。
- 不擅自引入确定性模拟、回滚、完整时间引擎或新插件；真实需要时再以单独决定和实验评估。

## 按层验证

按实际改动选择最小而有意义的验证；不要只为复制实现写测试，也不把文字修改升级成全游戏回归。

| 本次行为 | 优先证据 |
|---|---|
| 纯规则 | 正常输入与关键边界结果 |
| 子场景与表现 | 独立入口运行、依赖接线、碰撞/规则不受装饰变化影响 |
| 配置/运行状态 | 两实例共用定义时互不污染 |
| 公共接口接入 | 调用方适配、组合场景、清理和再次进入 |
| 共享状态变化 | 房主与客户端、拒绝路径、相关重复/竞争行为 |

导入或解析成功只证明对应检查完成，不能代替场景行为测试。
同机两进程不代表双机异地通过；测试替身不代表真实 RPC 接入。
无运行条件时完成能做的静态检查，逐项写“未执行”、原因和队友的复验步骤。

## 差异与本地提交

1. 检查实际 diff，剔除本次产生的无关缓存、导出物与凭据；保留应提交的资源和元数据。
2. 对照范围核验公共配置、主地图与接口变化，必要时同步真实设计与交接文档。
3. 沿用用户已有本地提交授权，按可解释小行为提交；没有 Git 就交付文件差异，不自行建仓库。
4. 暂存本次明确文件，避免把队友或用户的无关改动一起提交；不为清洁工作区丢弃已有成果。
5. 用户要求完整交付时，核对远端与任务分支后按当前交付流程继续：同步 main、rebase、验证、快进合并；只做本地提交时遵循该范围，不做角色资格校验。

涉及提交的验证对象应能对应具体提交；未提交成果交接时说明差异范围和基线。

## 可接手的交付

最终提供以下内容，可使用本包 [开发交接模板](模板/开发交接.md)：

- 完成的行为与必要接口变化、未完成项。
- 工作目录、分支/提交（存在时）、运行场景或命令、依赖前提。
- 已执行通过、已执行失败、未执行三类证据，以及下一步验证。
- 共享文件协调项、组合回归范围和已知限制。

需要远端交付时使用 GitHub 交付流程；没有其他技能也能准备任务关联、改动说明和验证材料，不以缺技能阻塞交接。
代码只读预审按改动需要安排；所有成员可合并 main，不强制 PR 或非作者批准，不把作者自测写成他人审核通过。
审核后出现新提交或冲突修复，明确变化并补审、重验受影响内容。素材和大文件按共用项目约束外置，不随代码提交。
未达到真实验收时不标 Done，不虚构 Godot、联机或 GitHub 操作结果。
