# 问题诊断

当出现报错、资源导入异常或实际行为不符合任务时读取。

## 先固定可复现对象

记录实际目录、版本、分支/提交或未提交差异、场景入口、预期与实际结果。
取第一条有关错误及调用位置，保留必要日志；不要只记录后续级联报错。
确认 Godot、AI、终端打开的是同一份工程，依赖分支和资源确实存在。

## 按证据缩小范围

| 现象 | 先检查 |
|---|---|
| 脚本解析/API 不存在 | 精确引擎版本、脚本语言、实际方法签名 |
| 节点或资源找不到 | 真实场景树、路径/UID、移动文件后的引用 |
| 场景可单跑，组合失败 | 注入依赖、实例生命周期、共享配置和加载顺序 |
| 双方状态不同 | 身份、权威入口、RPC 节点路径、是否仅发了本地信号 |
| 拾取或开门重复生效 | 权威端状态检查、幂等结果、是否重复连接回调 |
| 暂停或重进异常 | Timer/处理模式、残留连接、上局引用与状态清理 |

一次改变一个有证据的假设，重跑最小复现，再检查受影响调用方。
连续两次修改没有证据改善时停止堆补丁，保留差异并缩小复现；必要时请求结对定位。
不通过删测试、静默吞异常、随机延时或重造管理器掩盖原因；若暂时绕行，写明限制与后续任务。

## 环境缺失时

- 没有 Godot：可读代码、场景和差异，明确未导入、未解析、未运行。
- 没有真实工程：不要生成“已经修复”的结论；说明缺少哪些事实，可交付诊断或待接入材料。
- 没有两台机器或网络条件：记录已完成层次，给队友可执行步骤，不冒充异地验证。
- 诊断结论区分已证实原因、待验证假设和采取的改动，不把错误消失等同全部验收完成。
