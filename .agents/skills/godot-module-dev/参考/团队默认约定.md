# 团队默认约定

规范版本：0.5；日期：2026-10-18。此文件随每个技能独立分发，不依赖其他技能或作者的文档目录。

## 如何采用

当前用户明确决定、实际项目适用规则和已经采用的接口优先。本页是这支团队的默认工作方式，不冒充其他项目已采用的事实。项目没有规则/任务卡时，可据此继续明确的小任务；只有影响玩法或跨模块行为的关键未知项才需要决定。

先找用户指定目录、仓库根、真实 project.godot 与本次任务。缺 Git 不等于缺 Godot；多个 project.godot 要区分正式工程、示例和插件测试工程。没有作者仓库的指南属于正常情况，不要求寻找或下载它们。实际项目有 README、AGENTS.md、共同目标、结构说明、设计、任务或接口就先读共同方向，再读与本次有关的部分；没有时不假称已读，也不为了开工补齐整套文档。

## 起步游戏方向与动态事实

本团队起步参考：Windows、Godot 4 标准版/GDScript、单层 3D 世界、2D 纸片角色、固定斜俯视镜头，先小房间再 2–5 人合作逃脱原型。新工程可先用 Compatibility 和内置几何体；具体玩法、引擎精确版本、移动方案、网络运输、人数和美术资产必须由实际任务/工程确认。

联机原型默认优先房主权威，ENet 是可评估路线，不声称项目已有实现。背包、救援、幽灵等不是自动立项功能；没有真实需求不提前实现。不要给队友分配虚构姓名、Issue、提交或固定工时。

## 英文工程目录，中文说明

- 新 Godot 工程根目录、团队自有运行子目录与文件统一英文小写 snake_case；不用中文、空格或仅大小写不同的名称。固定工具文件名、第三方上游结构保留，中文界面文本可照常使用。
- 新正式工程未指定位置时默认 game/project.godot；已有正式入口不自动迁移，旧中文示例和用户电脑外层路径不顺手改名。
- res:// 从实际 project.godot 所在目录算起。game/features/player/player.tscn 是仓库路径；对应资源路径是 res://features/player/player.tscn。
- 按功能聚合相关场景、脚本与专用资源：app 组织入口，features 放功能，worlds 组装地图，ui 放界面，tests 放独立验证。shared 只放已有多个使用者的内容，addons 只在采用插件后增加。没有内容不建空目录。
- 中文设计、任务和运行说明写到项目已有任务源；没有既定位置而用户要求落盘时，优先根目录 docs/design/、docs/plans/、docs/tasks/、docs/verification/，中文文件名按批次加日期，长期共识保留单一来源并维护更新日期；已有 文档/ 不自动迁移。根目录工程可用 docs/.gdignore 排除导入。也可用 Issue；目录是建议输出位置，不是必须已有的输入。

## 架构边界

| 职责 | 做什么 | 不做什么 |
|---|---|---|
| 规则 | 血量、重量、容量、合法状态和结果计算 | 找 HUD、播放动画、依赖具体地图私有树 |
| 引擎/网络适配 | 物理、区域、RPC、对象生命周期 | 把客户端显示当最终事实 |
| 表现 | 纸片、动画、音效、相机、HUD；提出操作意图 | 直接决定伤害、归属、胜负 |
| 编排 | 接线、校验并串联当前流程、清理 | 包办所有模块业务 |
| 定义与运行态 | 参数定义按约定只读；本局状态独立 | 拾取后写回共享 Resource 定义 |

Node 不等于表现层；移动、碰撞、网络适配可以使用 Node，纯规则适合时才提成普通类。表现/规则分离也不等于客户端/服务器部署分离，房主可同时运行权威逻辑与本机画面。

公开方法提出行为，局部信号通知变化，上层提供依赖。不要写死跨模块 /root/Main/... 私有路径，不强制全局事件总线。机制接收中立输入，编排决定这一局的流程。物理用引擎步长，倒计时/撤离等共享结果由房主推进；首版不自建完整模拟引擎、回滚、回放或万能数据库。

## 联机正确性

客户端只发意图；权威端根据实际发送身份、玩家、阶段、目标、距离和归属验证，不相信客户端自报最终值。房主本机走同一规则入口，但本机输入不假装来自远程 RPC。结果应用要能处理重复/竞争请求，退出或重开清理上局引用与连接。

本地 Signal 不跨机器；RPC 路径、方法和来源规则按实际版本检查。去掉 GitHub 审批门槛不等于去掉游戏客户端的权限与输入校验。动画可展示动作，装饰播放速度不决定伤害/归属/胜负。

## 分工与工作区

每个任务一个明确主责、允许改动范围、验收入口、依赖与下一步。并行写入使用不同 clone 或正确 worktree，不让多人/多个 AI 在同一目录切分支。公共配置、主地图、接口与网络入口按当次编辑者协调。

保留用户和队友无关修改及暂存，不盲目 git add .、全量 stash、reset --hard 或 clean -fd。必要公共改动写清最小差异及影响方，不另造第二套管理器绕过协调。文件白名单是协作约定，不是操作系统隔离。

## GitHub 交付

所有成员可合 main，不查角色、collaborator 或审核资格，不强制 PR 或非作者批准。完整交付：独立任务分支 → 本地 commit → fetch 最新远端 main → rebase origin/main → 验证 → 普通快进推送 main → 核实结果。普通局部开发不会自动触发远端交付；用户指定仅本地/仅材料时遵循该范围。

常见实现是在已 rebase 并验证的任务分支执行 git push origin HEAD:main；remote 名和主线以实际目标为准。队友抢先更新时重新 fetch/rebase/验证，最多两次重新同步；不强推 main，不重写共享历史。实际认证、网络或服务器拒绝要如实报告，不改服务器规则。不因调用技能而建组织、仓库、发布、付费或给队友发消息。

## 素材和大文件

GitHub 仅保存代码、文本场景/配置、脚本 .uid 和必要说明。图片、音视频、模型、字体、源美术、压缩包、二进制 .scn/.res、工具目录、缓存/导出物和凭据不上传，不改走 LFS。英文素材路径通过仓库外渠道还原；素材版本、获取位置、校验值/大小、目标路径及对应代码版本要交接。

默认单文件达到 10 MiB 视作大文件；这是团队检查线，不是 GitHub 限额。gitignore 不能按大小过滤，也不停止已经跟踪的文件。检查暂存内容与 origin/main..HEAD 的全部待上传提交，避免先提交大文件再删除后仍上传历史；不要 git add -f 绕过。移出跟踪只处理确定文件，保留本地，不能自动清理远端历史。

新工程优先用内置几何体，让基础入口无素材包也能运行。运行确实依赖外置素材时，clone 后需先补齐，不能声称仅代码即可复现完整画面。脚本 .uid 保留；素材的 .import 旁文件随外置素材不入 Git，接收端重新导入并核对引用与需要固定的导入参数。

## 验证与收尾

区分已执行通过、已执行失败、未执行。静态检查、Godot 导入/解析、无界面启动、可见行为、同机多进程、双机、异地分别报告。没有引擎、素材或双机环境时完成可做部分，准确列缺项，不把日志/退出码、测试替身或旧审核冒充最终验收。

按改动验证有意义的正常与关键失败路径，不为纯文字变更强制全游戏回归。新提交、冲突解决或主线变化后检查受影响内容，记录对应版本。未满足实际验收不合 main、不标 Done。

技能指导行为，不能保证自动匹配、文件隔离或服务器限制。入口描述与默认隐式匹配允许 AI 按任务选择；显式点名更确定。实际项目当前规则和任务事实仍需传递，不能由技能替代。
