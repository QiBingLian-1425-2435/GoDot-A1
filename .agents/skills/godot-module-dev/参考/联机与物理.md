# 联机与物理

涉及共享状态、RPC、移动碰撞、计时或联机生命周期时读取。

## 沿既有权威入口接入

- 先确认实际网络路线、节点路径和权限。当前项目若采用房主权威 ENet，就复用既有会话和请求入口；别给模块另造网络管理器。
- 客户端提出意图；权威端从真实发送身份验证玩家、阶段、目标、距离和权限，不相信客户端自报最终值。
- 房主本机输入走同一规则入口，但本机并非远程 RPC，不误用只在远程上下文有效的发送身份。
- 权威端先完成一致状态变化，再分发表现结果；接收端验证来源，方法名叫 `confirmed` 不产生权限。
- 信号只在本地通知。RPC 的节点路径、方法签名和权限依实际工程核验，不能直接粘贴教学例子。
- 同一物品的竞争请求只能产生一次有效归属转移；重复开门不能重复扣道具。
- 对象与当前对局有明确生命周期：卸载后清理引用，拒绝失效目标或旧局消息，重开时初始化。

## 物理与时间

- 三维工程沿用实际 `CharacterBody3D`、`Area3D` 等节点与物理回调，不替换成二维示例。
- 速度、位移、单位和步长按真实 API 区分；`move_and_slide()` 使用速度，不把速度预乘一次 `delta` 当位移输入。
- 房主推进对局倒计时与撤离等待，客户端展示确认状态；按实际需求区分本机菜单与全局暂停。
- 沿用 Timer、处理模式和物理回调；没有需求不自行加入回放、回滚或统一模拟时钟。
- 动画可呈现动作，不因客户端装饰播放速度改变最终伤害、物品归属或胜负。

## 最少验证证据
