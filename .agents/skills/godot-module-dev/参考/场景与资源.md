# 场景与资源

需要创建/拆分子场景、替换表现、调整定义资源或移动文件时读取。

## 子场景可接手

- 沿实际工程目录，把相关场景、脚本和所属资源放在模块内；不把所有业务按文件类型重新洗牌。
- 先读现有场景树、脚本绑定、导出依赖和信号连接，再改节点名称或层级。
- 子场景在测试入口通过显式依赖运行；测试壳只模拟约定输入，不偷接另一套正式管理器。
- 父级连接协作者。子场景内部路径可以明确使用，外部依赖不要写死 `/root/Main/...`。
- 可复用交互物接收已选定目标的请求，不默认在每扇门/每件物品的 `_unhandled_input()` 中监听全局动作并直接改状态；简化键盘输入放明确的测试壳。缺公共输入或目标选择时说明协调项，不用运行时注册输入绕过范围。
- 需要持续提醒的必填依赖，可按现有风格加入编辑器配置警告；不要为一次参数漏填建立框架。

## 定义资源与实例状态

- 使用项目已有 `Resource` 定义或配置格式，新增前先查是否已有相同职责。
- 相同路径加载的资源可能共享实例；“定义只读”是约定，不是 Resource 自动提供的不可变性。
- 物品定义保存重量、图标等参数；持有人、剩余数量和本局状态放在独立运行对象。
- 确需复制运行资源时检查实际版本的复制语义与嵌套资源共享，不假定一次浅复制能隔离全部数据。
- 验证两个实例引用同一定义时，改变其中一份运行态不污染另一个或源定义。

## 表现替换与文件移动

- 保留玩法入口、碰撞主体、关键状态和既有接口；纸片、动画、音效按既有表现代理接入。
- 隐藏表现或停掉装饰动画后验证规则和碰撞；有意设计的玩法时序使用明确的权威逻辑。
- 文件移动优先用 Godot 编辑器，复核 `res://` 引用、UID、场景依赖和信号连接。
- 保留脚本 `.uid`；素材、外置素材的 `.import` 旁文件、`.godot/` 缓存和导出包按根目录 `.gitignore` 排除。素材版本与获取路径记入项目文档，接收端重新导入后验证引用。
- 独立运行成功后，再检查实际调用方；测试房通过不等于主地图接入完成。
