# 提交、rebase 与合并 main

更新时间：2026-10-17。本页是当前团队交付流程，取代旧版“必须提 PR、非作者批准、指定集成人合并”的约定。所有成员均可合并；不做角色或审批资格校验。仓库地址和分支仍要对准，运行验收仍要完成。

## 1. 开工：从最新主线建立任务分支

下面假设实际远端为 `origin`、主线为 `main`，命令应逐条执行、检查结果。任务分支名是示例，换成本次名称。

```powershell
git status --short --branch
git remote -v
git fetch origin
git switch -c feat/23-player-move origin/main
```

新建分支前妥善保留原有成果，不能带着不明修改开工。已有同一任务分支就回原分支；main 不存在时查清真实仓库状态，不自行创建另一条主线。

## 2. 保存本次开发成果

```powershell
git diff
git add -- game/features/player/player.gd game/features/player/player.gd.uid
git diff --cached
git diff --cached --check
git commit -m "fix(player): 修复贴墙移动抖动" -m "- 修正贴墙时的速度投影`n- 补充相关移动验证"
```

文件名和提交说明仅为示例，以上按工程位于仓库 `game/` 举例；已有其他布局时换成实际仓库相对路径。只暂存实际存在且属于任务的文件。按本包 [素材与大文件管理](素材与大文件管理.md) 排除工具配置、素材和大文件，检查本分支所有待推送提交。无关暂存不能混入这个 commit。

先 commit 是为了保存开发成果；同步 main 和 rebase 发生在远端交付之前。不要对未保存的修改直接 rebase。

## 3. 更新 main 基线，并在任务分支 rebase

```powershell
git fetch origin
git rebase origin/main
git diff --check origin/main...HEAD
git diff --stat origin/main...HEAD
```

`fetch` 更新本地记录的远端主线 `origin/main`，足以取得最新基线；不必先切本地 main 再切回来。`rebase` 把本任务提交重新接到该基线后面，提交 SHA 会改变。

冲突时查看 `git status`，理解双方修改并移除冲突标记，只暂存已解决的文件，再执行 `git rebase --continue`。不要把 `--skip` 当作通用解决方式。无法决定时保留现场说明，或 `git rebase --abort` 回到开始前。

只 rebase 本人独立任务分支。多人正在使用同一分支时先分离本次提交到独立任务分支，不改写共享分支。已推送过旧任务分支也不必强推它：本流程从当前本地 HEAD 直接交付 main；旧分支不要冒充最终交付版本。

rebase 完成后检查任务范围，运行受影响的 Godot 场景/检查。冲突处理导致的新修改须补验，不因旧提交通过过就跳过新组合验证。

## 4. 快进合入远端 main

确认当前仍是任务分支、工作区干净、验收满足后：

```powershell
git branch --show-current
git status --short
git rev-parse HEAD
git push origin HEAD:main
```

`HEAD:main` 表示把当前已经 rebase 和验证的任务提交快进合入远端 main。它就是本流程的合并动作；不生成额外 merge commit，也不需要先推任务分支或提 PR。记录推送前的 HEAD 作为交付提交。

普通 push 会拒绝覆盖不在当前历史中的远端提交。若队友抢先合入，留在任务分支重新 fetch → rebase → 检查与验证 → 普通 push，最多两次重新同步。不要增加 `--force`、`--force-with-lease` 或 refspec 前缀 `+`。

认证、网络、保护规则等错误按实际错误处理，不能当作主线更新无限重试；不主动查询角色、不修改服务器规则，也不声称已成功。

## 5. 核实并更新本地 main

```powershell
git fetch origin
git merge-base --is-ancestor HEAD origin/main
git switch main
git merge --ff-only origin/main
```

祖先检查成功说明交付提交已包含在当前远端 main；即使队友此时又合入新提交，也不应只用两端 SHA 是否完全相等判断失败。没有本地 main 时使用 `git switch -c main --track origin/main` 代替切换步骤。

本地 main 有独有提交时，`--ff-only` 会失败；保留这些提交并说明分叉，远端交付成功与本地主线未更新分开报告，不能 reset 丢弃。main 在其他 worktree 已检出时，到对应目录更新或只交接结果，不强行切换。

## 6. PR 与交接是可选扩展

默认无需 PR 或固定审核人。较大改动可以先请队友或 AI 预审，发现的问题仍须处理；不要求某个角色批准后才能合并。

只有用户要求 PR 时才创建或更新。正文写实际行为、任务链接、验证与未测项、素材依赖；多行正文用实际临时文件配合 `--body-file`，不虚构链接。用户明确只交 PR 或只提交本地时，按该范围停止。

没有 Git 或远端时交付本地文件、可复制说明与缺失步骤；不把示例当作真实执行结果。未完成验收时不合 main，不标 Done。

官方命令依据：[rebase](https://git-scm.com/docs/git-rebase)、[push 与快进限制](https://git-scm.com/docs/git-push)。
