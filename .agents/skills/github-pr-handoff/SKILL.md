# GitHub 交付与交接

团队当前流程：**新建任务分支 → 开发与本地提交 → fetch 最新 main → rebase → 验证 → 合入远端 main → 交接**。
保留技能名以兼容已有调用；PR 是可选记录方式，不是合并门槛。本包自带规则、忽略模板与提交检查脚本，可单独分发使用。

## 定位与范围

- 定位实际仓库根、Godot 工程根、当前任务和本次差异；技能目录不是工程根。
- 读取本包 [团队默认约定](参考/团队默认约定.md)。实际项目已有规则/任务优先，没有作者的指南目录不阻塞交付。
- 确认当前分支、暂存区、remote 与目标 `main`。这是防止提交错仓库，不检查成员角色、collaborator 或审核资格，也不要求运行 `gh auth status`。
- 所有成员都可自行合并。用户要求“交付/提交并合并本任务”时，完成必要的提交、rebase、合并和推送，不逐步要求批准。用户明确“只做本地提交/只准备材料”时止于该范围。
- 没有 Git、没有确定远端或实际推送被拒绝时，如实交付完成的部分与具体缺项；不自行建仓库，不把失败说成成功。
- 更新 skill 不等于现在执行真实远端交付；也不包含发布、部署、付费或给队友发消息。

## 文件与素材

按实际项目 `.gitignore` 和本包 [素材与大文件管理](参考/素材与大文件管理.md) 检查文件范围。缺少规则时使用本包 [忽略模板](模板/.gitignore) 补齐，有则合并而不覆盖用户规则。

- 提交代码、文本场景、文本配置、文档及脚本 `.uid`；素材和大文件走 GitHub 以外的共享渠道，不自动启用 LFS。
- 检查候选文件和任务分支尚未进入 `origin/main` 的全部提交历史，防止大文件先提交再删除后仍被推送。本版单文件达到 10 MiB 视作大文件，其他素材不论大小均按忽略规则排除。
- `.gitignore` 不按大小过滤，也不影响已经跟踪的文件；提交前检查实际暂存内容、大小和跟踪状态，不用 `git add -f` 绕过规则。
- 按明确文件或片段暂存，不盲用 `git add .`。保留无关未提交成果和他人暂存，不用 `reset --hard`、`clean -fd` 或全量 stash 清场。
- rebase 需要干净工作区。无关成果妨碍操作时，在独立工作目录处理能确定的本任务提交；不能安全分离就说明具体阻塞，保留原状。

提交前执行本包 [检查提交内容脚本](脚本/检查提交内容.py) 的 `--scope staged`，推送前执行 `--scope outgoing --base origin/main`；命令和无 Python 时的等价检查见 [素材参考](参考/素材与大文件管理.md)。脚本不修改仓库，不包含远端操作；失败先解决。不能执行时使用 Git 等价检查并准确标注方式，不把未检查当通过。

## 分支与合并

具体命令、冲突和并发处理见 [提交与远端操作](参考/提交与远端操作.md)。逐步执行并检查结果，失败后不要继续后续步骤。

1. 新任务从最新 `origin/main` 建短任务分支，如 `feat/编号-描述`；继续已有任务则使用原任务分支，不直接在 main 开发。
2. 完成局部实现和适当验证，检查并提交本任务文件。本地 commit 先保存成果，随后再 rebase 和远端交付。
3. `git fetch origin`，在任务分支执行 `git rebase origin/main`。使用实际远端名；不要用尚未更新的本地 main 当基线。不要对 main 或多人共用分支做 rebase。
4. 冲突时理解双方意图，逐文件解决并 `git rebase --continue`；不能决定时保留现场或 `git rebase --abort`，不盲选全部一方。
5. 检查最终差异，补验冲突处理和新主线影响的行为。新 SHA 的结论与旧版本区分；仍适用的验证不机械重跑。
6. 验收满足后，将当前任务 HEAD 普通推送到远端 main，完成快进合并；不强推 main。默认不要求先推任务分支、创建 PR 或找非作者批准。
7. 队友抢先更新 main 导致 non-fast-forward 拒绝时，仍在任务分支重新 fetch、rebase、检查和验证后再推。限制为两次重新同步；持续竞争或其他失败时交接准确状态，避免无依据循环重试。
8. 推送成功后读取远端 main，核对交付提交已在其历史中；再按需快进更新本地 main。保留任务分支作为交接依据，不自动删除他人分支。

如果实际服务器因保护规则或认证问题拒绝操作，报告准确原因；不擅自改保护规则或索取秘密。只有真实任务要求 PR 才准备 PR，创建成功后按当前环境要求关联到任务。

## 验证与交接

没有引擎或真实联机环境时准确标未执行。存在失败、依赖缺失或任务验收未满足时不合并，说清未完成部分；所有成员可合并不等于跳过验收。

```text
任务与变化：目标、行为、涉及范围和素材依赖。
版本：任务分支、rebase 基线、交付提交、远端 main 核验结果。
验证：已通过 / 已失败 / 未执行；必要入口与补验步骤。
状态：已本地提交 / 已 rebase / 已合入远端 main / 仅本地，分别陈述。
交接：剩余问题、外部素材版本与同步方法；PR 仅在实际存在时提供链接。
```
