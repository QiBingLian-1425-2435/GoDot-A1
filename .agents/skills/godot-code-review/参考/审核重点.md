# 按差异选择审核重点

本页只在相应改动出现时读取，不要求每个 PR 经过全部检查。架构解释见本包 [架构与模块边界](架构与模块边界.md)，实际项目已采用规则优先。

| 变化 | 重点追踪 | 有效验证例子 |
|---|---|---|
| 门、角色动画、UI 或音效 | 表现是否直接修改规则结果；更换或停播表现是否破坏状态与碰撞 | 停止装饰动画，已确认开门仍可通行；UI 重建不重发奖励 |
| 物品定义与背包 | 定义资源和实例运行态是否混用；重量规则是否钻进 HUD 或固定地图 | 两个实例共用定义，拾取一个不污染另一个；满容量拒绝后物品仍在原处 |
| RPC、拾取、结算 | 真实发送身份、目标、距离、归属、对局阶段由谁验证；重复意图是否重复生效 | 房主本机与客户端走同一确认入口；两人抢同一物品仅一次成功；重复结果不重复奖励 |
| 子场景、接线或主地图 | 跨模块依赖是否经明确接口提供；信号连接与销毁是否成对；引用是否随重命名保留 | 测试房独立运行；退出再开一局不重复连接；移动资源后引用正常 |
| 机制与编排 | 机制是否需要知道特定关卡树；协调代码是否包揽业务；接口调用方是否同步迁移 | 背包用中立输入计算；换测试房不改规则；接口迁移后全部实际调用方仍可运行 |
| 时间、移动、暂停 | 是否符合当前引擎 API 和权威推进方式；物理步长是否重复处理 | 不同帧率下结果合理；客户端不自行结束撤离；暂停范围符合已采用设计 |
| 公共配置与资源 | 引擎版本、Autoload、输入动作、资源元数据是否有无关变化 | 新路径导入；真实入口可用；脚本 `.uid` 保留；素材及其 `.import` 按忽略规则外置且有获取版本说明 |
| 纯文字、说明、重命名 | 语义与引用是否正确，有无把示例描述成实际事实 | 打开相应链接；核对名称和命令上下文；无需强制启动多人场景 |

## 可定位发现的写法

```text
[P1] game/features/items/pickup_adapter.gd:42
客户端可对已归属他人的物品重复发起请求；这里仅检查距离，随后直接转移归属。
房主状态入口未检查原归属，因此第二位玩家可能拿到同一实例。
证据：固定 head 的入口与状态写入调用链；当前未运行双机，需按任务步骤补验。
```

上例仅展示报告结构，不表示目标项目存在这些路径或缺陷。实际发现必须来自真实差异与上下文。

## 保留准确的验收边界

- 看到类型与调用合理，只能支持静态结论，不能证明无崩溃、正确碰撞或两端一致。
- 无图形的启动检查不能冒充动画、输入和 UI 验收；同机两个窗口不能冒充异地连通。
- 变更已通过但主线推进，优先检查触及的接口和组合场景；只有影响扩散时才扩大回归。
- 解决场景冲突后应查看最终场景树、引用和相关运行行为，Git 无冲突不等于兼容。
