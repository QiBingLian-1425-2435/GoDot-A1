# 游戏项目协作规则

这是候选模板。仅在实际项目初始化/规则配置任务需要时生成或合并到目标根目录；保留用户已有约定，不将本模板原样覆盖已有 AGENTS.md。启用时删掉本说明，填写真实工程入口和版本。

- 从真实工作目录定位仓库根和 project.godot。开工先读项目已有的共同目标、结构说明、相关接口与任务；已有规则、接口和用户决定优先；不存在作者的历史文档不阻塞工作。
- 新工程根目录、运行子目录和文件统一英文小写 snake_case；新正式工程可用 game/project.godot；已有根目录工程保留，不嵌套第二个工程。中文设计、任务和说明沿用文档区，无既定位置时用根 docs 分类管理并记录日期。已有中文示例不自动改名。
- 按功能组织代码。规则不依赖 HUD/动画；Node 可以承载物理与网络适配；上层接线，表现读状态并提意图。定义资源与本局运行态分离，不写共享定义改变某个实例状态。
- 客户端提出请求，权威端校验并确认共享结果。本机房主走同一规则入口。信号不是跨机器同步，GitHub 合并无审批门槛不代表游戏输入无需校验。
- 并行写入使用独立工作目录和任务分支。主地图、公共配置与接口由当次编辑者协调；保留无关成果，不盲目全量暂存、清理或覆盖。
- 按当前任务选择可用技能：建工程/目录迁移用 godot-project-setup；架构边界用 godot-architecture-design；拆任务/接口用 game-task-design；实现修复用 godot-module-dev；只读审核用 godot-code-review；完整代码交付用 github-pr-handoff。不强制串行经过所有技能。
- 技能不存在时按已明确目标和本规则继续，不要求先安装才能工作；发现的技能依描述按需选择，不声称每次保证自动触发。
- 所有成员可合 main，无角色/审核资格校验，不强制 PR。完整交付使用任务分支、本地提交、fetch main、rebase、验证、普通快进推送 main；只做本地时遵循用户范围，不强推 main。
- 素材、大文件、个人工具目录、缓存、导出物和凭据不上传 GitHub，也不改走 LFS。保留文本场景/配置与脚本 .uid；外置素材按版本、获取位置和英文路径交接。
- 提交前检查暂存内容，推送前检查全部待上传历史；默认单文件达到 10 MiB 视作大文件。gitignore 不能按大小筛选，也不影响已跟踪文件。
- 记录实际版本和入口，区分已通过、已失败、未执行。导入、无界面启动、画面/输入、同机、双机和异地测试不互相冒充。未满足实际验收不合 main、不标 Done。
