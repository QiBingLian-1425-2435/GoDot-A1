# Godot 工程初始化与目录管理

交付一个入口明确、目录可解释、队友能接手的工程底座；已有工程则只处理本次必要的结构调整。本包可单独复制使用，不依赖作者仓库的指南或其他技能。

## 先判定本次任务

1. 读取本包 [团队默认约定](参考/团队默认约定.md)，定位用户指定工作目录、仓库根和真实 Godot 工程根；技能目录不是工程根。目标项目已有规则/任务时读取相关内容，没有历史指南也可按包内约定开工。
2. 查找已有 `project.godot`，区分正式工程、教学示例、插件测试工程。多个工程时结合项目说明和本次目标定位；不能仅选搜索到的第一个，也不因已有教学示例就覆盖它。
3. 分清用户要实际建工程、调整目录，还是只讨论结构。只讨论时交付建议；用户已要求实施时完成对应工作，不重复请求常规步骤许可。
4. 实际版本、渲染器、语言与运行平台从当前基线读取。全新工程先检查可用引擎和已采用路线，再选最少配置；记录实际版本，不把旧教程版本当当前安装版本。
5. 按需读取本包 [目录操作与交接](参考/目录操作与交接.md)，其中包含完整的起步目录、模块归属与迁移检查。需要创建忽略规则或项目指令时使用本包模板，不要求外部文档存在。

## 始终遵循的目录规则

- **之后新建的 Godot 工程根目录和团队自有的运行子目录统一英文小写 `snake_case`**，例如 `game/`、`features/player/`、`worlds/prototype_room/`。不用中文、拼音代替职责名、空格或仅大小写不同的名字。
- 运行文件同样沿用英文 `snake_case`。`project.godot`、`.godot`、`.gdignore` 等固定名称保留；第三方插件的上游结构不随意重命名。中文界面文本和节点显示内容不受目录规则影响。
- 中文指南、设计、任务沿用项目文档区；无既定位置时优先根目录 `docs/`，按 design/plans/tasks/verification 分类，文档文件名继续中文。根目录工程可使用 `docs/.gdignore` 排除文档导入；已有 `文档/` 不自动迁移。既有中文示例和用户电脑的外层路径不因这条未来规则而批量改名。
- 新正式工程没有指定位置时，默认建议仓库内 `game/project.godot`；已有正式工程在仓库根或其他已采用位置时保留入口，迁移只在本次目标包含迁移时实施。
- 关联场景、脚本与专用资源按功能靠近放。新增目录应有实际内容和职责，不提前创建整套空模块、万能管理器、Autoload、插件或网络框架。
- 素材和大文件按根 `.gitignore` 与项目素材规则外置，运行所需素材仍须落到约定的英文路径；初始底座优先用引擎内置形状，避免缺素材无法启动。

## 从零初始化

1. 保留现有文档、忽略规则、示例和用户成果；只向确定的新工程位置写入，不覆盖另一份配置。初始化工程不自动初始化 Git 或创建 GitHub 仓库。仓库没有 `.gitignore` 时可从 [忽略模板](模板/.gitignore) 创建，有则合并缺项；需要统一 AI 入口时按 [项目指令模板](模板/AGENTS.md) 生成/合并实际规则，不覆盖用户已有约定。
2. 配置 `project.godot`、主场景和本次必要输入/窗口设置，创建能观察到结果的最小房间或用户指定入口。采用中的 3D 路线使用对应三维节点，不先开发背包、联机或完整对局。
3. 只拆当前确有必要的入口、功能和地图文件。一个小场景已足够就不强制增加一层 app 或模块框架；需要玩家复用时才拆独立玩家场景。
4. 核对所有 `res://` 引用以实际工程根计算；任务卡中的文件范围同时写清仓库路径，避免把 `game/features/` 与 `res://features/` 混用。
5. 用匹配版本的 Godot 导入并启动入口，有运行条件时验证本次可见行为。让引擎生成脚本 `.uid` 并保留，不伪造 UID，不提交缓存或个人工具配置。
6. 在仓库中文文档中记录版本、工程路径、启动入口、操作方式、目录职责、未测项和外部素材依赖。验证失败就处理原因或准确说明，不能把“生成文件”写成“已运行”。

## 新需求落位与骨架演进

新增功能目录、决定文件归属或扩展现有骨架时，读 [新需求落位与骨架演进](参考/新需求落位与骨架演进.md)。先归属现有模块；独立职责才新建模块，跨模块接口/状态归属改变才展开架构调整。输出最小落位决定后继续实现，不强制普通局部任务先重做架构。

## 已有工程的目录管理

- 只增加目录：先查现有功能边界，把文件放到现有所属模块；确实新增职责才建目录，不每做一个任务就重排项目。
- 移动/重命名：列出旧路径、新路径、调用方和需要变更的任务/设计链接。优先用 Godot 编辑器移动资源；涉及脚本连 `.uid` 一起移动，外置素材也要调整同步说明。
- `.tscn`、`.tres`、脚本加载路径、主场景、Autoload、输入/导出配置、测试入口和文档按实际引用检查。存在网络节点路径时另核对 RPC/场景路径；不把所有同名字符串盲目替换。
- 仅改大小写时通过临时英文名完成两步改名，并核对 Git 的实际改名差异；不能只在 Windows 文件管理器看一眼就判定跨平台正确。
- 旧中文目录若不在任务范围内，记录为待迁移，不顺手搬整库。用户明确要求迁移时保留可回退基线，验证引用与场景，而非只改文件夹名字。

## 交付

交付实际工程入口、精简目录树与职责、变化/迁移映射、运行方法、已通过/失败/未执行的验证，以及下一位成员如何继续添加模块。
目录方案不等于真实初始化；静态引用检查不等于 Godot 启动或视觉验收。远端交付按包内团队约定执行，有 `github-pr-handoff` 时可选用；其他技能缺失不阻塞独立交付。
