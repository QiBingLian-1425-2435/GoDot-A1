# 探索脱困与房间准入

日期：2026-10-21；任务 RECOVERY-009；基线 e3b5186，分支 codex/exploration-recovery。当前 AI 协调 Main、Session、Steam、人物物理和 UI；本轮仅本地实现与提交，不沿用此前任务的 main 合并或推送授权。

## 用户确认的目标

- 从主菜单及 Steam 页面移除 IP 直连入口，Steam 失败提示不再引导使用 IP。ENet 保留为内部自动验证入口。
- 游戏 Esc 菜单增加“脱离卡死”，房主选择有支撑、胶囊不重叠且有可走出口的位置；保留背包、生命和地图，10 秒冷却，加载中拒绝请求。
- 检查零号区地表及洞穴的真实碰撞，重点覆盖树、箱组、岩石、集装箱及狭窄接缝；修复走入后无法退出的情况。
- 用户明确选择：仅基地允许加入；进入探索地图时锁房，原队友继续游玩，返回基地后重新开放。

## 状态与接口

UI 只发 unstuck，不接收客户端自报坐标或目标玩家。Session 从发送身份调用 BaseModel；BaseModel 持有冷却和 relocation_seq，PlayerPhysics 只提供安全落点查询。物理适配记录本地图近期安全位置，切图清空；历史失效时搜索附近有出口的安全点。客机预测和远端插值按 relocation_seq 清除旧位置，避免脱困后被旧预测拉回。

SteamService 发布 join_state 并调用 setLobbyJoinable；Main 根据已确认地图同步门槛。Session 在真实 peer_connected 事件再次检查基地、加载和人数条件；关闭准入不取消现有成员资格。客户端分别在房间数据验证和 lobby_joined 后检查锁定，处理出发与加入的竞态。协议更新为 a1_bunker_v5，必须同版本构建。
