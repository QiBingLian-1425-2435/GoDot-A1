# 零号区全局地图验证

日期：2026-10-23。用户要求进入第一张探索地图后能查看全局地图和队友位置。

## 行为与边界

- 零号区地表按 `M` 打开全屏俯视地图，`M` 或 `Esc` 关闭；地图打开期间移动、瞄准和射击输入被阻止。
- 2026-10-25 优化交互：鼠标滚轮或 `+/-` 按钮在 100%–300% 间缩放，按住左键拖动地图，“定位自己”会放大并把本机标记移到视图中心；每次重新打开恢复完整地图视野。
- 金色标记为本机，青色标记为同一房间队友，并显示成员名。标记只读取现有房主权威移动快照中的 `players[*].pos`，不新增 RPC、不修改共享状态或协议版本。
- 地图底图由已还原的零号区素材通过 `python tools/generate_global_map.py` 生成到外置素材目录，并登记进 `asset_manifest.json`，随现有地图素材一起校验和打包；图片继续不进入 Git。
- 当前只开放零号区地表全局地图。基地不显示；神秘山洞按 `M` 会提示当前范围，避免拿地表底图错误表示洞穴。

## 已执行验证

- 静态/专项：Godot 4.5.2 headless 运行 `tests/base/global_map_test.gd`，通过底图加载、世界坐标到地图坐标、两名玩家状态、开关生命周期、缩放上下限、定位自己、拖动边界和视图重置断言。
- 可见界面：Godot 4.5.2 Compatibility 渲染 1600×900 截图，确认真实零号区俯视底图、金色本机点、青色队友点、名字与关闭提示可见。证据为忽略目录 `artifacts/base_tests/global_map.png`。
- 主入口 headless：`--smoke --no-steam` 通过，输出 `DUCKOV MAIN SMOKE PASS players=1 obstacles=43`。
- fast 回归共 11 个入口，10 个通过；`duckov_actor_animation_test` 保留当前工作区既有的 `visible NPC resumes idle animation` 时序失败（64 条断言仅此 1 条失败），与地图 UI 路径无关，未改写为通过。
