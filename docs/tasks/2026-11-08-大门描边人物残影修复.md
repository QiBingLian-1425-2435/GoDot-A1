# 大门描边人物残影修复

## 原因与实现

已完成本地修复；本次不改地图、碰撞、交互判定、角色动作、共享材质或网络协议。

- 原交互描边将玩家的网格复制到独立遮挡视口，但没有复制 Skin 和 Skeleton3D 路径，因此蒙皮模型按绑定姿势出现在遮挡掩码中，而不是画面里的当前动作。这产生了截图中的错位人形轮廓。
- 原掩码只用红色通道，黑色同时表示背景和遮挡物；扩边把玩家造成的遮挡切口也当成目标外缘，从而沿人物画白线。
- `interaction_outline.gd` 的副本现在复用原网格对应的实时 Skin 和骨骼节点路径；跟随原动画的 GPU 蒙皮，不另烘焙模型、不每帧复制骨骼。BlendShape 权重同步到副本。
- 空间遮罩 shader 用 R 标识交互目标、G 标识遮挡物，背景保持零；合成 shader 禁止在遮挡物通道上画描边。大门本身仍显示白色外缘，玩家/其他遮挡物只参与遮挡，不成为交互高亮目标。
- 保留本地 E 提示目标驱动、观察者隔离、无目标/切图清理以及箱子/NPC 描边。

## 验证与测试维护

- 新 `outline_occlusion_test.gd` 通过真实当前基地大门检查男女角色的站立、走路、奔跑和蹲行，确认玩家仅为遮挡物、副本复用实时骨骼，并在渲染器中核对双方骨骼 RID 相同。
- Headless 34 项通过；可见 GPU 58 项通过。GPU 用实际合成 shader 单独输出透明视口，避免窗口缩放和场景火焰影响截图差分；八种姿势的遮挡边界白色 alpha 像素均为 0。
- `--suite interaction_outline` 五次运行通过：原交互规则/可见基地门和零号区箱子、NPC 内部纹理检查及新增遮挡检查。继续验证无提示观察者无描边、离开清理、搜索切查看和加载清理。
- 原 NPC 测试固定坐标已与当前可编辑基地布局不符，初次运行未找到目标；改为读取实际医疗站 Marker，并添加无掩码时立即失败，避免错误后挂起。同时将对比图统一到掩码分辨率，适应可选窗口尺寸。最终 NPC 内部 6613 像素差异低于原 1% 阈值。
