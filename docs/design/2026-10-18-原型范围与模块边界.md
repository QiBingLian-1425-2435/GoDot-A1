# 原型范围与模块边界

更新：2026-10-19。当前范围以用户要求迁入的新地下基地 Demo 为准，覆盖旧旅店的具体玩法边界；历史版本可从 Git 查阅。

正式结构与接口统一见[项目结构说明](2026-10-18-项目结构说明.md)，本轮具体范围及旧→新映射见[迁移计划](../plans/2026-10-19-地下基地Demo迁移.md)。不维护两套相互矛盾的当前状态契约。

当前 BaseModel 的 state 包含 players/drops/targets/shots/phase(base)，玩家保存 bag(24)/stash(48)/equipment/magazines/credits/生命耐力饥渴/位置朝向/动画序号。Session 从真实发送者确认 token、序号和动作，再调用 model.command；客户端不传最终库存、伤害或持久存档。物品只在某个玩家容器或世界掉落中拥有一个 UID，转移先校验完整操作；失败不部分提交。脱离房间的客机物品不持久化，房主/单人有独立存档。

动作与载荷：move(direction,aim,sprint,crouch,ads)、transfer(from,index/slot,to,target)、split(container,index,count)、use/drop/equip(index)、unequip(slot)、pickup(uid)、sort(container)、reload/fire/rest/craft/buy_ammo/reset_targets。UI 不调用原旅店 start/pickup(item_id)/possession 动作。全员同协议 a1_bunker_v1 和精确构建。

基地安全区域无玩家互伤；医疗、制作、购买和重置靶由权威验证距离与物资。武器弹匣独立保存，不能切枪补满。角色动作时长只作表现与状态同步，不决定最终命中或物品归属。物理节点仍由合适的 Godot Node 承担。

含房主最多 5 人，Steam 与 ENet 不能混用连接同一房间，房主保持运行，退出即结束；不做房主迁移、掉线续局、野外任务或原版游戏存档兼容。入口 main/Session/state/地图本轮由当前 AI 集成；后续按功能目录认领，不各自新增全局状态或网络管理器。
