# 原型范围与模块边界

更新：2026-10-18。本轮经用户确认，复刻 `.references_code/123` 队长初稿，取代旧灰盒实现；正式 Steam 目标保持不变。先读[项目共识与目标](2026-10-18-项目共识与目标.md)。

## 行为与分工边界

包含单层旅店、固定斜俯视、纸片角色、12 件遗物/6 类定义、12 kg 容量、360 秒对局、4 秒个人撤离、AI 队友、怪物、倒地救援、尸体搜取、受限观战、自愿附身、临时房间收益、大厅与重开。参数来自初稿，不是永久玩法定案。暂不包含门、新地图、主动战斗、自由幽灵、持久仓库和 Steam。

| 目录 | 责任及允许写入 |
|---|---|
| app/main | 组合、键鼠到屏幕方向意图、接线；本轮公共集成点 |
| app/network | 会话生命周期、真实发送者身份、RPC 白名单、轮次与速率校验、快照 |
| features/match | 唯一本局 state、玩家/轮次、命令分发、tick、跨系统调用；公共契约需集成协调 |
| features/inventory | 定义只读；纯容量/重量/价值计算；地面/背包/尸体的原子归属转移 |
| features/player | 真实物理主体和适配；actor_view 只显示纸片与动画 |
| features/enemies / rescue | 怪物导航与命中，生命/倒地/救援/死亡与尸体生成 |
| features/extraction / possession | 撤离入账与结算；请求/同意/解除共享视角 |
| features/companions / navigation | AI 意图；中立障碍数组、寻路和视线，不引用 UI |
| worlds / ui / audio | 地图碰撞、快照表现、意图界面与声音；不确认最终归属 |

系统方法接收 ctx（当前 MatchModel）及明确参数，只能由房主/离线权威调用；不保存另一份状态或查找外部场景路径。每系统有自己的计时/导航变量，match 中少量转发属性保留初稿测试夹具接口。跨模块改 state 字段必须协调 match 和调用方，避免成员分别修改同一流程。

## 公开调用契约

- `MatchModel.state: Dictionary`；`obstacles: Array[Rect2]`，由地图在开局前注入。`add_player/remove_player/get_player/reset_lobby/start_round/command/tick` 保留初稿职责。
- `InventoryRules.weight(items) -> float`、`value(items) -> int`、`can_add(items,item,capacity=12.0) -> bool`。旧整数重量改为浮点以支持 1.5 / 2.5 kg；定义每局深复制生成实例。
- `MatchModel.motion_solver: Callable` 由 app 注入，调用 `(id,from:Vector2,offset:Vector2) -> Vector2`；玩家 id 为真实身份，0 留给怪物。实际主场景每次移动经过 Godot CharacterBody3D；不挂载场景的规则测试才使用矩形求解。
- `Session`：`host(port=24567) -> Error`、`join(address,port=24567) -> Error`、`offline()`、`start_solo()`、`send(action,payload={})`；`model/local_id/mode/connection_status`；`state_changed()`、`notice(text)`。旧 `close()` 已由 offline 生命周期代替，调用方和旧测试入口同步迁移。
- `HUD.action_requested(action,payload)`；主场景把请求交 Session。`update_view(state,id,mode,connection)` 只显示确认状态。

动作：move 携 direction:Vector2 与 interact:bool；pickup 无载荷；drop 携 item_id:int；start/lobby 仅房主；possession_request 携 target:int；possession_accept/possession_decline/detach 无载荷。E 按下拾取一次，长按以 move.interact 推进持续救援/搜尸。

## 协议与状态

本机/客户端输入 → Session → 真实发送者与阶段/轮次/距离/负重验证 → 权威原子转移 → 快照 → 角色和 HUD。

所有端使用同一 `Main/Session` 节点路径。move 走不可靠有序通道 1；动作可靠通道 0；完整快照约 12 Hz，经可靠通道 2（控制快照通道 0）。跨通道递增 snapshot_seq 防止旧快照回退。超过 0.35 秒未刷新输入自动停止。客户端不能 start、替别的玩家提交身份或写最终状态。尚无公网带宽优化/预测/回滚。

新快照字段为 phase(lobby/raid/results)、round、time_left、players、loot、corpses、monster、events、total_banked、round_value、snapshot_seq。players 保存 id/name/pos/hp/status/bag/capacity/down_left/extract_progress/revive_progress/result_value/possessing/request_from/bot/connected 等。位置 Vector2(x,z) 映射三维 Vector3(x,0,z)。旧 positions/inventories/extracted 等快照已经替换，必须全员同一版本，不支持旧灰盒协议混连。

物品唯一存在于地面、玩家包、尸体或已撤离锁包之一。死亡/未撤离断线转交尸体，收益不入账；撤离一次锁包和入账，房主仍服务；超时保留已撤离者收益。全部无人存活/倒地时结算，房间累计仅内存保留。附身需活人同意（AI 自动同意），只共享视角，死亡/撤离/断线与任一方解除均清理。
