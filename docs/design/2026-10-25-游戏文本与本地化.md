# 游戏文本与本地化

2026-10-25；TEXT-001；分支 `fork`。按用户要求统一管理游戏文本，当前提供简体中文和英文，协议更新为 **a1_bunker_v16**。

## 静态目录

| 文件 | 用途 |
| --- | --- |
| `features/localization/zh_cn.json` | 默认简体中文，607 个稳定文本键，包含格式模板与单位 |
| `features/localization/en.json` | 同键英文翻译 |
| `features/localization/locales.json` | 可选语言、自称名称与文件名 |
| `features/localization/sources.json` | 文本键对应的实际源码位置，由审计工具更新，不进入运行包 |
| `features/localization/game_text.gd` | 延迟格式化、接收端解析、语言偏好与显示绑定 |

范围包含菜单、设置、HUD、帮助、物品名/描述/类型/稀有度、背包、交易、制作、营地、容器、救援、语音提示、地图、3D 标牌、人物标签、窗口标题及联机状态/通知。资源名、协议字段、日志、纯数字初值、按键符号和玩家自行输入的名字属于运行数据或技术标识。原有工程名称继续作为固定应用/存档身份；Main 的可见窗口标题读取目录，保持旧存档路径。

## 定义、状态与显示

定义与共享状态中的 `⟦item_catalog.013⟧` 是稳定引用，不受语言改变影响。数值、物品 kind、设施 ID、容器 UID 仍使用原来的字段。UI 只发原动作意图，规则仍由房主确认。

```gdscript
const Texts = preload("res://features/localization/game_text.gd")

# 模板留在静态 JSON；状态和通知保留模板及参数。
var message := Texts.format("⟦base_hud.015⟧", 3)
Texts.bind(label, message)
```

`Texts.format` 将模板和参数序列化为可组合的字符串引用，保持现有 String 通知/RPC 接口。`Texts.resolve` 在本机显示时展开引用并格式化；房主中文、客机英文可以显示同一条确认结果。通过 `Texts.clip` 延迟截取默认名字，避免截断引用；Steam 名字、房间名等外来文本在接入时用 `Texts.literal` 保持原样。

`Texts.bind` 记录节点属性的原始表达式；列表通过 `add_item` / `set_item_text` 记录各行表达式。切换语言时更新仍存活的绑定并重绘自绘控件。节点释放后绑定随节点释放。文本输入框的用户输入保持不变。

设置 → 语言可即时切换；偏好写入本机 `user://language.cfg`。修改不进入共享状态，不要求重进房间，不改变游戏规则或房主语言。默认 `zh_CN`；缺译、空译或 printf 参数类型签名不匹配时回退中文；未知键显示 `[missing:key]` 便于定位。递归展开限制为 24 层，解码不允许对象实例化。

## 维护步骤

1. 修改文案只编辑语言 JSON；新增文案使用稳定新键，不重排或复用已有编号。`sources.json` 可按文件/行号定位原用途。
2. 代码引用新键；动态数值使用 `Texts.format`。定义与网络通知保留引用，不提前翻译；显示使用 `bind`、列表包装或自绘处的 `resolve`。
3. `%s`、`%d`、`%.1f` 等参数的数量与类型顺序必须与中文一致，`%%` 是百分号。需要调换参数语义时同步调整模板与调用，不靠翻译偷偷交换数值含义。
4. 新语言在 `locales.json` 登记，并将对应 JSON 加入运行依赖白名单。当前交付语言要求完整；运行时仍保留逐键回退能力。
5. 执行 `python tools/check_game_texts.py --write-sources` 更新来源索引，再执行不带参数的审计。审计检查重复键、缺译、参数签名、失效/闲置引用、内嵌中文、标牌英文和导出依赖；新增显示出口仍需代码检查和运行验证。
6. 执行 `python tools/run_base_tests.py --suite localization --godot "实际路径"`；保留新增脚本 UID。运行目录与 `export_presets.cfg` 已包含目录 JSON。
