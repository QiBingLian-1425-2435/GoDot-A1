# Steam 联机接入方案

更新：2026-10-18。已明确采用 Steam 跨网络组队游玩作为正式目标，非局域网。共同方向以[项目共识与目标](2026-10-18-项目共识与目标.md)为准。本版本只实现 ENet，不包含 Steam 插件或假的“Steam 已连接”按钮。

玩家体验目标：通过 Steam 创建房间、邀请/加入，不要求同一局域网、不填写公网 IP、不配置端口映射。ENet 仅保留为开发验证入口。

技术目标：房主权威保持不变，Steam Lobby 负责发现与组队，兼容的 Steam MultiplayerPeer 负责传输，沿用对局 RPC。房主仍需在线；不做房主迁移和重连。

Steam Datagram Relay 是 Valve 的网络中继服务；使用条件、可用范围以 Steamworks 官方文档为准。不能把“不租专用服务器”理解为“正式 Steam 发布没有费用”：Steam Direct 每个应用有上架费用。测试 App ID 不能冒充正式发行身份。

实施顺序：

1. 选定团队实际 Godot 版本、GodotSteam/MultiplayerPeer 维护中的兼容构建；记录下载链接、版本、散列与许可证。当前未下载二进制，不给未知 API 拼接一个假适配器。
2. 独立测试场景验证 Steam 初始化、回调推进、当前账号；明确开发 App ID 与两位测试成员各自已登录 Steam 的环境。
3. 验证大厅创建、邀请/加入、人数上限、游戏开始锁加入、离开与失败清理。大厅与游戏数据传输是两个职责，不能创建大厅成功就标联机完成。
4. 给 Session 增加明确运输选择与 Steam 配置入口，接入真实 MultiplayerPeer；保持 Main 权威 ID/发送者识别与 RPC 契约，必要变化同时修改协议和调用方。
5. 两个 Steam 账号、双机、不同网络下验证实际同步、拾取竞争、超重、提前撤离、客户端断开和房主退出；再扩五人。

Steam 插件 DLL、SDK 和导出包按外部依赖管理，不上传 GitHub；将版本/获取链接/目标英文路径写进素材依赖清单。仅靠 .gitignore 不能按大小过滤；提交前检查暂存文件与待推送历史，10 MiB 为团队检查线。
